# LabFlow 0.2.1 人工测试指南

这份清单用于补齐真实环境才看得出的结果。优先做 A、B、C，约 15–20 分钟（不含安装 Node、配置代理或排查网络）；D 按现成环境抽样，E 可与 C 合并。项目端已检查离线判题、不可用提示、模型保存和重启恢复；队友重点验证自己的真实服务、Windows 和日常浏览器。

仍待外部环境确认的是：实际 CC Switch / OpenAI 兼容服务请求、Windows 真机启动、Edge/Chrome 原生图片拖放，以及鼠标和触控板下的画布操作。离线规则可判定空答案、缺失的结构及登记的准确名称；未知措辞和主观题应显示“无法判断”，并注明评价来源。HTTP 配置格式见 [模型接入说明](ai-backends.md)。

## 准备

- 使用原始 `LabFlow-0.2.1-team.zip` 的全新解压目录。运行分享包只需 Node.js 22 或更新版本，不需安装项目依赖或 Codex。测试数据会写入该目录下的 `.labflow/`；分享时只转发原始 ZIP。
- Windows 离线启动：双击 `Start-LabFlow.cmd`。macOS 离线启动：双击 `Start-LabFlow.command`。如果网页没有自动打开，使用启动窗口给出的本机网址，并保持窗口运行。
- 配置 HTTP 服务时，先在本机终端进入解压目录，按你的 CC Switch/服务实际支持的协议设置环境变量，再从同一终端运行 `node start.mjs`。这保证启动进程能继承环境变量。Windows PowerShell 示例：

  ```powershell
  $env:LABFLOW_AI_BACKEND = 'openai-compatible'
  $env:LABFLOW_API_BASE_URL = 'https://你的服务提供的API根地址/v1'
  $env:LABFLOW_MODEL = '你的模型ID'
  $env:LABFLOW_API_STYLE = 'chat-completions' # 或 responses；按服务实际支持选择
  node start.mjs
  ```

  macOS/Linux 可在终端设置同名变量后运行 `node start.mjs`。`LABFLOW_API_BASE_URL` 填 API 根地址，不要把 `/chat/completions` 或 `/responses` 追加到末尾。远端服务须使用 HTTPS；本机回环服务可使用 `http://localhost`、`http://127.0.0.1` 或 `http://[::1]`。仅当服务需要认证时，才用你已经采用的本机安全方式为启动进程提供 `LABFLOW_API_KEY`；不要把密钥写入脚本、截图、聊天或回报模板。
- HTTP 状态显示“已配置”或“首次请求时验证”仅表示配置项可读，不表示代理已连通。必须发起真实模型请求才算端到端通过。HTTP 配置使用环境变量；`CODEX_BIN` 指向 Codex 可执行文件，不能填写 API URL。

## 需要队友完成的检查

### A. Windows 启动和离线使用（约 3 分钟）

**准备：** 找一台可用的 Windows 电脑和浏览器；本项不需要 Codex CLI 或已登录的 Codex。

**操作：** 在解压目录双击 `Start-LabFlow.cmd`。先在 Western Blot 学习界面展开总流程，记下六个阶段名称，再进入“回忆训练”的细节补全。保留空白并检查一次；然后按刚才看到的名称填入全部空项再检查。这里测功能，不把看过参考的表现当成独立记忆成绩。若模型状态为未连接，打开模型设置查看具体提示。

**通过标准：** 服务窗口保持运行，网页可用；准确答案由“规则检查”判为正确，空白项显示有错误或未完成，模型不可用时仍可继续本地流程操作。不能因缺少 Codex 阻断启动。

**失败回报：** 记下 Windows 版本、Node 版本、启动脚本显示的错误和页面状态。若启动失败，先确认系统已能运行 Node.js 22+；不要为了复现未登录状态而退出账号或删除凭据。

### B. Edge/Chrome 原生操作和小屏可读性（约 5 分钟）

**准备：** 使用常用的 Windows Edge 或 Chrome，并将窗口设为 1280×720、浏览器缩放 100%。在“回忆训练”选择有配图的阶段。没有配图的阶段会禁用配图题，换到标注有配图的阶段再测。

**操作：**

1. 用鼠标或触控板把一张图片卡拖到流程块；记录图片是否归位。若拖放失败，点图片卡，再点目标流程块，验证备用操作是否可用。
2. 在顺序重建或整段重建中，从一个步骤卡右侧连接点拖到下一步左侧连接点，确认箭头出现。
3. 点选刚建的连线并按 `Delete` 或 `Backspace` 删除，再点工具栏“撤销”，确认连线恢复。等界面显示草稿已保存后刷新页面，确认布局和答案仍在。
4. 点“展开画布”，检查图内文字和连线；点“退出专注”，确认侧栏与草稿恢复。再查看题目、提交按钮、反馈和右侧学习伙伴，确认没有遮挡。学习总览的根节点应直接连向全部六阶段，去往第二排的线应绕过第一排卡片，不应看起来像第一排的子步骤。

**通过标准：** 原生拖放成功，或备用点击方式能正确归位；右到左连线、删除、撤销及保存后刷新恢复均符合操作结果；1280×720 下主要文字和提交控件可读、可操作，没有关键内容被裁切或互相遮挡。若仅原生拖放失败而备用点击可用，应单独标为“拖放失败、备用操作通过”。

**失败回报：** 说明浏览器和版本、鼠标/触控板、浏览器缩放、窗口分辨率及失败步骤。截图只保留页面，不附个人数据目录。

### C. 真实 HTTP/CC Switch 服务和模型持久化（约 7–10 分钟）

**准备：** 使用自己的 CC Switch 或其他 OpenAI 兼容服务。确认它支持 Chat Completions 或 Responses，以及结构化 JSON 输出，准备 API 根地址和模型 ID。

**操作：**

1. 按“准备”中的方式设置环境变量并启动分享包。状态区和模型设置里记录显示的后端与模型。若状态只说已配置，先不要算通过。
2. 进入 Western Blot“检验”，选择“封闭液选择”情境，提交：“所有磷酸化抗体都必须用 BSA，换掉奶粉就一定能解决。”默认应只显示判定和来源，不应自动列出错误位置或标准答案。确认实际调用来源（HTTP 模式显示“服务评价”）；仅本地规则结果不能证明服务连通。
3. 依次点“给我一个提示”“再具体一点”：前者给大方向，后者只聚焦刚提交答案中的一个问题并说明原因。再点一次具体提示，应保持同一个点。修改答案后若未重新检查，具体提示应要求先检查新答案；完成重新检查后，再主动点“详细点评与修订”。这时才检查完整点评是否核对抗体说明书、区分封闭液与一抗稀释液，并避免保证 BSA 必定解决。记录不同判定的原文供复核。
4. 留在封闭液题，向学习伙伴问：“封闭液和一抗稀释液有什么区别？只解释这一点，不要给本题完整答案。”答复应解释所问概念，而不是重复宽泛提示。然后换到“大蛋白转膜”情境，再问：“为什么不能只凭 40 kDa 对照有信号，就断定 250 kDa 目标一定不表达？”应回应证据范围，不编造固定转膜参数。若不支持该问题，应明确说明限制。
5. 在“模型设置”中选择服务真实支持的模型并保存，确认“当前模型”显示该值。停止服务，在同一解压目录和相同环境配置下重新运行 `node start.mjs`，刷新页面，检查当前模型仍是所选值；再发起一次真实请求，确认重启后仍能调用。

**通过标准：** 至少一次主观答案检查实际到达服务并返回可用结果；来源标签与真实后端一致；默认评价克制，具体提示和详细点评按请求逐级展开；重启后保存的模型仍显示，并能再次成功请求。保存成功提示或“已配置”状态本身不算连接成功。

**失败回报：** 记录所选协议、页面显示的非敏感错误文字、失败发生在连接还是模型响应阶段，以及服务是否接受该模型和结构化 JSON 输出。隐藏 key、完整私有地址及包含请求凭据的日志；只提供脱敏后的状态码或错误摘要。不要上传 `.labflow/`。

### D. Codex 已登录/未登录状态（按现成环境抽样，约 2–4 分钟）

**准备：** 若测试电脑已经装有并使用自己的 Codex CLI，可在其当前登录状态下启动分享包；若有一台本来就未登录或没有 Codex CLI 的 Windows 环境，也可验证该状态。无需为了这项测试安装 Codex、登录、退出登录或删除凭据。

**操作：** 已登录环境中查看右上角状态和模型列表，并发送一个简短的流程问题或主观情境答案；现成未登录/无 Codex 环境中查看不可用提示，再验证本地客观题仍可检查。两种状态都应使用各自电脑当前实际状态记录。

**通过标准：** 已登录环境的请求来源与 Codex 一致并能得到响应；未登录环境能清楚说明服务不可用，草稿保留，本地规则检查继续工作。若没有现成未登录环境，回报“未测试”，不要改动账号状态来制造它。

### E. 教学反馈和 AI 情境抽样（与 C 共用服务，约 3–5 分钟）

**操作：** 选定一个情境并记下题目名称，再点“AI 出题”。它应生成同一情境的表述变式，不能偷偷切换考点；“换一题”才负责切题。把题目中的每个实验事实与当前节点来源及情境参考核对；重点看它是否把“候选方案”说成必然结论、是否捏造固定时间/电流/浓度，是否能区分证据、推测和未知。如果生成失败，应清楚回退到当前预置题。主动点“查看完整答案”时，才应展示完整参考并标注辅助练习。

**通过标准：** 反馈直接回应答案与问题；不把不确定原因说成唯一原因，不补造当前来源没有支持的条件；宽泛提示、单点提示和完整答案按请求逐步展开。情境生成内容通过人工核对才记为通过；明确回退是安全失败路径，但不算成功生成质量验证。

**失败回报：** 保留题目、你输入的测试答案/问题、页面反馈和相关来源节点名称。标出哪一句事实不符或超出来源，并提供脱敏截图。
