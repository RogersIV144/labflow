# LabFlow 0.3.0 · 可控制、可回看的实验场景

基于队友提交 `3f40b9f` 的 WB / JTC 三维实验台继续迭代。重点是笔记本上的阅读、操作与教学衔接，不增加独立 agent 框架或实验日志。

## 变化

- 用阶段导航与阶段内步骤条建立顺序感；下拉框仍可直接跳转全部 19 / 8 步。操作正文和按钮文字加大，压缩重复标题，让播放控件留在首屏。
- 镜头根据窗口比例与器材边界构图；支持全景、当前操作、俯视和自由旋转。低帧率下的镜头过渡使用实际经过时间。新增独立器材台，暂时隐藏其他设备及背景，排除遮挡。
- 器材按钮可通过键盘使用；三维点击也可打开器材的全部相关步骤。准直透镜与傅里叶透镜分开定位；采集相机和显示器一起入镜。
- 播放支持 0.5× / 1× / 1.5×；可暂停、拖动进度、直接回看某项操作，重置同时恢复夹层、曝光和光轴参数。切换步骤或离开浏览器页时暂停。
- 修正跨步骤误计完成的状态竞争。只有从头播放至末项才记一次「本次完整播放」；手动跳至末项不计数，演示不增加独立训练成绩。此计数只保留在当前场景会话，不作为历史日志。
- JTC 的二维图和三维屏幕使用同一套输入/输出状态：采集前不提前给出结果，第二次输入保留回显功率谱，第二次采集后才显示相关结构。光束加粗以便在小画布中辨认，仍为非定量示意。
- 「流程与笔记」定位当前参考节点，可继续附图、修订和记录；「回忆这一阶段」进入相应阶段的练习。回到流程图时重新适应画布。
- 先加载约 24 kB 的操作界面，再加载 Three.js 场景。场景静止后停止连续绘制，离屏或页面隐藏时取消帧循环；减少动态偏好下停止循环动画，状态切换直接到位。WebGL 丢失可重试，加载失败仍保留文字导览。
- JavaScript harness 入口通过当前 Node 启动，不再依赖系统把 `.mjs` 当作可执行程序。用于修复队友记录的 Windows 集成测试启动路径；Windows 实机结果仍待验证。

## Issues 核对

2026-10-19 在 GitHub 查看了全部 11 条开放 issue 的列表，没有发现专门针对新增三维场景的条目。与本轮有关的是 [#2 界面可读性](https://github.com/RogersIV144/labflow/issues/2)、[#3 顺序感](https://github.com/RogersIV144/labflow/issues/3) 和 [#10 结果解读](https://github.com/RogersIV144/labflow/issues/10)。本轮改善这些诉求在场景模式中的表现，没有关闭 issue，也没有把本次场景验收视为所有既有诉求都已完成。

## 验证与边界

具体记录见 [0.3.0 QA](qa-0.3.0.md)，队友复测见 [人工测试指南](manual-testing-0.3.0.md)。三维图形仍是教学模型，条带与光学输出是合成图；不提供测量精度或实验室操作能力认证。

Three.js 场景块仍约 590 kB（gzip 约 151 kB），构建仍提示超过 500 kB；延迟加载改善导览出现的时机，不代表总下载量已经降低。未测 FPS、电池续航或 Windows 显卡兼容性。模型接口回归使用合成 harness；本轮未重新进行真实模型语义质量评测。
